Destinations are not playable in this build."). It is not `TLM_MQ02`. No road is started, no destination exists, nothing is paid, no stage of `TLM_MQ02c` and no flag of the writing is set.

If the side quest's ledger report is available, Pritchard's existing line with its two buttons comes first, as before: "There's something else from that train." does the report and nothing else; Continue goes on to the hub.

## 4. The copy

1. Offered only in the pike's follow-on. `AboutTheCopy` first settles an old intent from the inventory (`Acknowledge`).
2. If a copy is held, was issued, or an intent is unacknowledged: the same speech with one neutral button (`TLM_MSG_MB_DocketIssued`, "Continue") and a line of interface text: "One review copy only. No second copy is given.", or the pending diagnostic. No button promises a copy.
3. Otherwise the speech with "Take the review copy." / "Leave the copy.". On Take, `IsOpen` is read again; then, in `GiveCopy`: the count is read (above zero: nothing); then, with no call into the game in between, the flags are tested and `CopyGrantPending` is set; then `AddItem(ReviewCopy, 1, false)` on the player, once; then the count is read, for up to a second (ten looks; the game is never asked again); above zero: `CopyIssued = true`, `CopyGrantPending = false`.
4. Still zero: **fails closed.** `CopyGrantPending` stays set, nothing is claimed as given, the script log gets a line beginning `TLM_MercyBriefing: FAIL CLOSED:` with the count and both flags, and the screen's edge "Review copy hand-over unconfirmed. None is given again. Report this to the tester." The three briefs still work. The book is never asked for again; if it is later found in the inventory, the next visit acknowledges it.
5. Dropped, stored or removed: `HasReviewCopy()` is false and `CopyIssued` stays true; no second copy. Back in the inventory: true again. Nothing else is taken from the player; the book is in no alias and is not a quest object.

`HasReviewCopy()` counts the book's record in the inventory. It is the precursor of the writing's `docket_2298_held`; `mq02c set 16` has no counterpart here by design.

### A working copy made before the end-of-line rules

Adding the rules changes how Git writes the four files out; it does not rewrite files that are already there and that Git regards as unchanged. A working copy on a machine that converts line ends, checked out before the rules, therefore keeps those four files with CRLF, and `verify` goes on failing there, saying so, until they are written again. Tried in a clone with conversion on: `git checkout-index --force` leaves them as they are; this does it:

```bash
git diff --quiet -- tools/win/world-details-artifact.json tools/win/world-natural-artifact.json tools/win/world-story-artifact.json tools/WorldSliceBuilder/expanded-artifact.json
```

Only if that reports no change (exit status 0), delete those four files and check them out again:

```bash
git checkout -- tools/win/world-details-artifact.json tools/win/world-natural-artifact.json tools/win/world-story-artifact.json tools/WorldSliceBuilder/expanded-artifact.json
```

A fresh clone needs none of this. Nothing here touches a Git setting outside the repository's own `.gitattributes`.
