Preparation is a coordinator task, not something this launcher installs: create MO2 profile `TLM-World-Preview` with LocalSaves and LocalSettings true. Close both game and Mod Organizer. Double-click `tools\win\Play-World.cmd` for the already-installed personal F4SE route. PowerShell `Play-World.ps1` defaults to the managed Fallout4.exe; `-UseF4SE` opts into the existing version-gated loader. `-ValidateOnly` checks prerequisites without creating files or launching. Unknown mods/plugins, absent profile, shared saves, mismatched world hash, nonzero scenario, private probes and active game/manager cause refusal.

The owned startup batch executes `coc TLM_WS_Clearing` followed by seven SPECIAL values of four on a fresh main-menu COC character. It does not load a save, change level, perks, inventory, caps, derived health/AP, cheats, quest stages or aliases. There is no save-load hook. The only configuration writes are this dedicated profile's `sStartingConsoleCommand` and `bAlwaysActive`, restored with read-back after both game and manager close. Other INI keys are preserved. MO2 also remembers its selected profile as usual.

Look around, try the cabin furniture, then quit normally without saving and let the launch window finish. No successful play/walking/controller claim follows from a launch or script check. If MO2 remains open, close it too. This fresh shell is not the old QASmoke playtest.

An interrupted session recovers on the next invocation; do not delete its note to bypass a cleanup error. No process is killed. Uninstall/rollback is simply not using this launcher after successful cleanup; it never installs an artifact.
